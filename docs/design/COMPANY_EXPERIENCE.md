# Company 화면의 목적과 경험 계약

이 문서는 회장이 `Company`에서 무엇을 판단하고 어떤 근거를 따라가는지 정의한다.
설명은 한국어로 작성하며 따옴표와 코드 표기의 UI label은 영어를 사용한다.
화면 계약의 원본은 [Application Shell and Views](../architecture/APPLICATION_SHELL_AND_VIEWS.md#work-and-agents--is-the-ceo-using-the-company-well), 구현 기록은 [MAC_APP](../implementation/MAC_APP.md)이다.
구성원·책임·인계의 의미는 [공유 계약](../architecture/CONTRACTS_AND_STATE.md#company-agent-identity-and-membership)을 따른다.
이 문서는 새 API·조직·권한·스케줄러를 정의하지 않는다.
v3의 독립 Company 화면·업무·실행·Trace 구현 범위는 [현재 coverage](UI_PURPOSE_CONTRACT.md#coverage),
실제 화면 확인은 v3 QA (retained local evidence; excluded from product Git)에 기록한다.
본문의 이전 시안 평가는 설계 시점의 감사이며 현재 구현 상태를 대신하지 않는다.

공통 부품은 [Primitives](./UI_PURPOSE_CONTRACT.md#primitives), 자료·조작 상태는 [Shared states](./UI_PURPOSE_CONTRACT.md#shared-states)를 따른다.
아래 ID는 구현 주석·검증·화면 검토가 같은 목적을 참조하기 위한 고정 식별자다.
`Company`는 기존 주 메뉴 하나이며 `Executions`, `Activity history`, `Trace`는 그 안의 보조 보기다.
기본 읽기 순서는 회사 문맥 → 우선 업무와 최근 변화 → 관련 구성원 → 선택한 근거다.
고정 부서, 빈 직원 슬롯, 필수 `New work` 경로, 에이전트가 생성하는 화면은 두지 않는다.

<a id="o-01"></a>
## O-01 · Company — 어느 회사의 운영을 보는가

- **목적 / 회장 질문:** 지금 어떤 회사·환경을 보고 있으며 관측을 신뢰할 수 있는가?
- **자료·근거:** 검증된 회사/환경 식별자, 현재 읽기 범위, 각 자료의 출처·최근 관측 시각을 사용한다.
- **표현·배치:** 상단에 `Company`, 회사명, `Live` 또는 `Test`, 관측 문맥을 둔다. 실행 개수를 대표 성과로 확대하지 않는다.
- **행동:** 지원되는 회사 전환과 현재 범위 확인을 제공한다. 전환은 업무 생성이나 기존 회사 정지를 요청하지 않는다.
- **상태:** `Connecting`, `Disconnected`, `Access restricted`, `Not observed`를 구별하며 연결 실패를 빈 회사로 표시하지 않는다.
- **검증:** 회사 전환 뒤 이전 구독·선택·자료가 새 회사 이름 아래 남지 않는다. 도메인이 없어도 `Company`를 읽을 수 있다.

<a id="o-02"></a>
## O-02 · Priorities — CEO는 회사를 무엇에 쓰는가

- **목적 / 회장 질문:** 지금의 우선 업무와 기대 결과가 회사 목적에 맞는가?
- **자료·근거:** 현재 운영 책임에 연결된 업무, 우선순위 근거, 기대 결과, 검토 조건과 보존된 설명을 참조한다.
- **표현·배치:** 본문 위에 짧은 `Priorities` 요약과 관련 업무를 둔다. 자바스크립트가 우선순위나 계획을 임의로 생성하지 않는다.
- **행동:** 업무를 열거나 `Discuss in room`으로 선택한 주제를 기존 대화에 가져간다. 단순 열람으로 메시지를 보내지 않는다.
- **상태:** 설명이 없으면 `No explanation recorded`와 관측된 업무를 함께 표시한다. 미응답이 운영 중단을 뜻하지 않는다.
- **검증:** 앱을 열거나 갱신해도 모델 호출·새 업무·새 방이 생성되지 않는다. 작성자·근거·다음 조건까지 따라갈 수 있다.

<a id="o-03"></a>
## O-03 · Work — 무엇을 하며 실제로 무엇이 달라졌는가

- **목적 / 회장 질문:** 구성원이 맡은 일, 지금 하는 행동, 최근 결과와 막힌 점은 무엇인가?
- **자료·근거:** 업무 목적, 책임 배정, 현재 실행, 결과 참조, 대기 조건·의존성의 관측을 함께 읽는다.
- **표현·배치:** 넓은 본문에 비교 가능한 행을 둔다. 업무명 → 담당자 → 최근 변화 → 상태·다음 조건 순서로 읽는다.
- **행동:** 행을 선택하면 [Work detail](#o-07)을 연다. 지원하는 상태·담당자 필터는 현재 선택과 함께 보존한다.
- **상태:** `Working`, `Waiting`, `Blocked`, `Handing over`, `Not observed`를 구별한다. 임의 진행률은 넣지 않는다.
- **검증:** 대기 업무도 찾을 수 있고 한 행에서 책임자와 다음 조건을 확인한다. 업무가 없다고 필수 생성 폼을 열지 않는다.

<a id="o-04"></a>
## O-04 · Latest update — 요약은 누구의 설명이며 무엇을 근거로 하는가

- **목적 / 회장 질문:** 지난번 이후 중요한 변화가 무엇이며 설명과 사실이 일치하는가?
- **자료·근거:** 보존된 메시지·업무 요약·산출물과 실제 관측을 사용하고 작성자, 작성 시각, 대상 기간을 유지한다.
- **표현·배치:** 업무 행에는 짧은 변화만, 긴 설명은 상세에 둔다. `Agent summary`와 `Observed`를 출처와 함께 구별한다.
- **행동:** 원래 메시지, 실행 또는 정확한 산출물을 연다. 질문은 원본과 작성자를 보존하여 대화 입력에 첨부한다.
- **상태:** `Partial coverage`, `Stale`, `Source unavailable`을 표시한다. 최신 관측이 오래된 작성 내용을 몰래 덮어쓰지 않는다.
- **검증:** 요약의 주장을 원본으로 확인할 수 있다. 도구 이벤트마다 알림·요약 항목을 만들거나 숨은 모델 추론을 표시하지 않는다.

<a id="o-05"></a>
## O-05 · Members — 누가 지속적으로 책임지는가

- **목적 / 회장 질문:** 회사의 실제 구성원은 누구이며 지금 무엇을 맡고 있는가?
- **자료·근거:** 인증된 논리 principal, 버전이 있는 프로필, 현재 책임 배정, 연결된 업무·실행을 사용한다.
- **표현·배치:** 업무 옆 또는 아래에 작은 `Members` 목록을 둔다. 이름·일관된 식별 이미지·책임·관측 상태가 아바타 장식보다 먼저다.
- **행동:** 구성원을 선택하면 [Member detail](#o-06)을 연다. `Former members`는 과거 기여를 찾는 보조 필터다.
- **상태:** 실행 중이 아니어도 구성원을 유지한다. 대기·미배정·제한·인계·퇴역·미관측을 필요한 근거와 함께 구별한다.
- **검증:** 모델/세션 교체가 새 직원으로 나타나지 않는다. CEO 한 명인 회사도 완전한 목록이며 임의 부서나 보조 세션을 직원으로 만들지 않는다.

<a id="o-06"></a>
## O-06 · Member detail — 이 구성원이 왜 필요하고 무엇을 기여했는가

- **목적 / 회장 질문:** 현재 책임의 이유, 기여한 결과, 비용과 남은 의무는 무엇인가?
- **자료·근거:** principal과 프로필 revision, 배정 이유, 현재/과거 업무·실행·산출물·대화·인계 참조를 읽는다.
- **표현·배치:** 공통 상세 패널의 위쪽에 이름·책임·현재 업무를, 아래에 결과·실행·비용·보존된 지식 참조를 둔다.
- **행동:** 관련 업무·실행을 열거나 개인방에서 논의한다. `Knowledge`는 허용된 자료를 열며 모델의 내부 기억을 노출한다고 약속하지 않는다.
- **상태:** 한시적 도움과 지속 구성원을 구별한다. 과거 프로필이 없으면 `Historical profile unavailable`을 표시한다.
- **검증:** 프로필 이름 변경이 원래 저자나 다른 principal을 합치지 않는다. 인원수·실행 횟수를 효율 점수로 환산하지 않는다.

<a id="o-07"></a>
## O-07 · Work detail — 이 일을 왜 하며 무엇을 확인해야 하는가

- **목적 / 회장 질문:** 이 업무의 필요성, 기대 결과, 현재 판단과 다음 검토 조건은 무엇인가?
- **자료·근거:** 목적·요청/발생 배경·부모 업무·책임 배정·실행·판단 기록·산출물·미확정 효과를 참조한다.
- **표현·배치:** 상세 상단에 목적·담당자·최근 변화·다음 조건을 둔다. 기술 ID와 긴 기록은 아래의 펼침 영역에 둔다.
- **행동:** `Executions`, `Related work`, `Artifacts`, `Usage and costs`, `Trace`를 같은 상세 문맥에서 연다.
- **상태:** 기대 결과와 실제 결과를 구별한다. 판단 기록이 없어도 관측 자료를 숨기지 않으며 원래 의도를 추측해서 채우지 않는다.
- **검증:** 실행을 열기 전에 업무 목적과 책임자를 이해할 수 있다. 상세 조회·대화 진입이 새 실행이나 업무를 생성하지 않는다.

<a id="o-08"></a>
## O-08 · Related work — 누구에게 무엇을 맡기고 무엇이 돌아왔는가

- **목적 / 회장 질문:** 하위 업무가 왜 생겼고 결과가 원래 일에 어떻게 연결되는가?
- **자료·근거:** 기록된 부모/자식 업무, 요청자, 배정 principal, 실행, 반환 결과, 미해결 책임을 사용한다.
- **표현·배치:** 업무 상세에 깊이가 제한된 관계 목록을 둔다. 장식적 조직도나 이름으로 추론한 관계선을 그리지 않는다.
- **행동:** 부모·자식 업무를 선택해 상세를 교체하고 원래 업무로 돌아온다. 필요한 다음 관계만 명시적으로 더 읽는다.
- **상태:** 반환 대기, 결과 수신, 결과 검토와 실행 종료는 각각의 근거를 따른다. 관측되지 않은 자식은 완료로 간주하지 않는다.
- **검증:** CEO 실행 종료가 자식 업무 완료·권한 회수·외부 효과 해소로 전파되지 않는다. 관계 조회는 무한 재귀로 늘어나지 않는다.

<a id="o-09"></a>
## O-09 · Observation and waiting — 기다리는가, 막혔는가, 모르는가

- **목적 / 회장 질문:** 일이 멈춰 보이는 이유가 정상 대기인지 개입이 필요한 문제인지 알 수 있는가?
- **자료·근거:** 실제 다음 wake 조건, 의존성 상태, 마지막 발생/수신 시각, 출처별 최신성·누락을 사용한다.
- **표현·배치:** 상태 옆에 `Waiting for …`, `Blocked by …`, `Last observed …`를 짧게 적는다. 색 하나로 건강 상태를 합치지 않는다.
- **행동:** 대기 조건이나 막힌 의존성을 열어 확인한다. 갱신은 관측을 다시 읽으며 새 실행을 시작하지 않는다.
- **상태:** 활동, 권한, 자료 최신성, 외부 효과를 독립적으로 표시한다. 열린 프로세스나 최근 HTTP 응답만으로 `Healthy`를 만들지 않는다.
- **검증:** 정상 대기는 오류색으로 표시하지 않는다. 시간 경과·앱 재접속만으로 미확정 호출이나 대기 작업의 결과가 바뀌지 않는다.

<a id="o-10"></a>
## O-10 · Executions — 실제로 어떤 시도가 있었는가

- **목적 / 회장 질문:** 같은 구성원·업무의 현재 실행과 이전 시도가 어떻게 달랐는가?
- **자료·근거:** admission, 실제 instance binding, 시작/종료 관측, 결과, 사용량·비용·산출물 수와 그 집계 범위를 읽는다.
- **표현·배치:** `Company`의 보조 목록 또는 업무 상세에 행으로 표시한다. 구성원·업무·상태·기간으로 좁혀 비교한다.
- **행동:** 실행을 선택해 [Execution detail](#o-11)을 연다. 실패 행에 자동 재시작을 연결하지 않는다.
- **상태:** 요청된 실행과 실제 실행 인스턴스를 구별하고 미관측 시작/종료 시각과 기간은 `Unavailable`로 남긴다.
- **검증:** 한 구성원의 겹친 실행·과거 실행이 각각 보인다. 현재 실행이 없어도 이력을 읽고 원래 업무로 돌아갈 수 있다.

<a id="o-11"></a>
## O-11 · Execution detail — 설명과 실행 근거가 일치하는가

- **목적 / 회장 질문:** 이 시도가 무엇을 하려 했고 실제로 어디까지 진행됐는가?
- **자료·근거:** 업무·principal·assignment·instance/generation·native turn·도구 호출·결과 영수증을 참조한다.
- **표현·배치:** 목적·담당자·최근 변화·다음 조건을 먼저, 관측·Trace·산출물·사용량을 뒤에 둔다. `Stop execution`은 정확한 대상에 고정한다.
- **행동:** 허용된 도구 입력/결과와 원본 증거를 펼치거나 선택 실행의 제어를 연다. 상세 조회에 모델 응답은 필요 없다.
- **상태:** 에이전트 설명, native turn 종료, 프로세스 종료, 자원 반환, 실제 답변·파일 결과를 서로 다른 근거로 표시한다.
- **검증:** `native_turn` 조회가 비었거나 텍스트에 완료가 적혔다고 성공 처리하지 않는다. 성공한 도구 호출도 업무 전체 완료를 대신하지 않는다.

<a id="o-12"></a>
## O-12 · Stop execution — 무엇을 멈추며 무엇이 남는가

- **목적 / 회장 질문:** 지금 선택한 실행을 멈추면 어떤 요청이 차단되고 어떤 효과가 남는가?
- **자료·근거:** 실제 중지 대상·현재 revision·호출자 권한·제어 intent·Runtime 종료·반환 영수증·잔여 효과를 사용한다.
- **표현·배치:** 선택 실행 상세에서 고정 제어 프레임을 연다. 대상·범위·현재 상태와 남는 의무를 명령 버튼 가까이에 둔다.
- **행동:** 지원되는 정확한 제어만 실행하며 고정 입력·요청 키를 보존한다. 보조 세션이 별도 중지 가능한 인스턴스인 것처럼 꾸미지 않는다.
- **상태:** `Requested`, `Accepted`, `Stopping`, `Terminated`, `Resources returned`, `Unresolved`는 관측된 단계만 표시한다.
- **검증:** timeout·재접속 뒤 원래 명령을 조회하며 중복 요청하지 않는다. 실행 정지를 주문 취소·포지션 청산·금융 정산으로 표시하지 않는다.

<a id="o-13"></a>
## O-13 · Trace — 주장부터 실제 효과까지 연결되는가

- **목적 / 회장 질문:** 어떤 판단·요청·도구 실행이 이 결과를 만들었으며 어디가 미확정인가?
- **자료·근거:** Work → 책임/실행/instance → native/tool → Gateway admission/dispatch → 결과 또는 미확정 → DB/파일/외부 영수증 → 비용 참조를 읽는다.
- **표현·배치:** `Company`의 선택 업무·실행에서 보조 타임라인을 연다. 긴 Trace만 본문으로 넓히며 주 메뉴를 추가하지 않는다.
- **행동:** 기간·업무·구성원·도구·출처·결과로 좁히고 이벤트의 허용된 원문을 펼친다. 관련 파일이나 도메인 효과는 원본 소유 화면으로 연결한다.
- **상태:** 실제 연결만 선으로 표시한다. `Missing span`, `Partial coverage`, `Unknown outcome`을 남기며 숨은 모델 추론은 제공하지 않는다.
- **검증:** source·발생/수신 시각·단계·ID와 오류를 확인할 수 있다. 긴 payload는 제한하여 읽고 허용되지 않은 내용은 오류·내보내기에도 노출하지 않는다.

<a id="o-14"></a>
## O-14 · Activity history — 특정 업무 밖에서 무엇이 바뀌었는가

- **목적 / 회장 질문:** 실행뿐 아니라 권한·연결·제어 변경 중 지금 상태를 설명하는 기록은 무엇인가?
- **자료·근거:** 각 소유자의 실행·권한·연결·운영 제어 기록과 검색 범위·보존 기간·색인 최신성을 사용한다.
- **표현·배치:** `Company` 안의 `Activity history` 보조 보기에 검색과 시간순 목록을 둔다. 기본 업무 화면을 로그 스트림으로 바꾸지 않는다.
- **행동:** 업무·구성원·기간·활동 유형으로 검색하고 이벤트에서 읽기 쉬운 상세, 필요하면 [Trace](#o-13)로 이동한다.
- **상태:** `No matching records`와 `Search unavailable`을 구별한다. 결과 수·필터·페이지에도 현재 공개 범위를 적용한다.
- **검증:** 같은 이벤트가 재수신되어도 중복 행이나 효과를 만들지 않는다. 기록 누락을 회사에 변화가 없었다는 결론으로 표시하지 않는다.

<a id="o-15"></a>
## O-15 · Usage and costs — 결과를 얻는 데 무엇을 썼는가

- **목적 / 회장 질문:** 이 업무·구성원의 실제 기여와 비용, 아직 반영되지 않은 부담은 무엇인가?
- **자료·근거:** 모델·compute·도구·데이터 사용량, 실제 비용 영수증, 통화·단위·기간·귀속 방식·미가격 항목을 읽는다.
- **표현·배치:** 업무/실행 상세에 비교 가능한 비용 행과 coverage를 둔다. 큰 실행 횟수나 임의 효율 점수로 대체하지 않는다.
- **행동:** 비용의 원본 호출·영수증을 열고 회사 전체 경제 결과가 필요하면 등록된 도메인 화면으로 연결한다.
- **상태:** `Unpriced`, `Partial coverage`, `Shared cost`, `Owner-paid`를 근거에 따라 구별한다. 누락이나 미배분을 0으로 합산하지 않는다.
- **검증:** 원본 identity/revision으로 중복 집계를 막고 기간·범위를 명시한다. 기본 앱이 P&L이나 임의 비용 배분 공식을 소유하지 않는다.

<a id="o-16"></a>
## O-16 · Artifacts — 무엇을 만들었고 어떤 버전이 근거인가

- **목적 / 회장 질문:** 보고된 결과의 실제 파일과 원본, 변경 이력은 어디에 있는가?
- **자료·근거:** 작성 principal·업무/실행, Catalog 게시 영수증, 정확한 workspace/revision/path, 관측된 검증·사용 기록을 읽는다.
- **표현·배치:** 업무/실행 상세에 파일명·유형·작성자·revision·게시 상태의 목록을 두고 공통 미리보기로 연다. 전체 검색은 `Library`를 재사용한다.
- **행동:** 정확한 파일을 미리보고 저장하거나 사용 가능한 이전 revision을 비교한다. 원래 업무·Trace·대화 참조를 보존한다.
- **상태:** `Uploaded`, `Published`, `Validated`, 실제 사용은 별개다. `Revision unavailable`과 읽기 제한을 표시하며 최신 파일로 대체하지 않는다.
- **검증:** 새 manifest 게시 뒤에도 선택했던 revision을 정확히 요청한다. 파일 본문은 안전한 제품 뷰어로 읽으며 실행 코드나 생성 UI로 설치하지 않는다.

<a id="o-17"></a>
## O-17 · Handover — 책임이 바뀌어도 무엇이 이어지는가

- **목적 / 회장 질문:** 누가 책임을 넘겨받았으며 이전 실행의 의무와 미확정 효과는 남아 있는가?
- **자료·근거:** 기존/후임 principal, assignment revision, 실제 종료·인계 기록, 열린 업무·비용·파일·wake·미확정 효과의 원본을 읽는다.
- **표현·배치:** 구성원/업무 상세의 `Handover` 영역에서 이전 책임 → 현재 책임과 남은 항목을 보여준다. 새 운영 화면을 만들지 않는다.
- **행동:** 원래/후임 배정과 잔여 항목의 증거를 확인한다. 지원되지 않는 인계를 UI 버튼이나 복사된 프롬프트로 수행하지 않는다.
- **상태:** `Handing over`, 실제 배정 변경, 후임 실행, 잔여 효과 해소를 분리한다. 프로세스 종료만으로 인계 완료를 표시하지 않는다.
- **검증:** 후임이 이전 저자·손실·비용·의무를 덮어쓰거나 권한을 자동 상속하지 않는다. 불확실한 기존 게시/효과를 완료로 가정하지 않는다.

<a id="o-18"></a>
## O-18 · Context and return — 근거를 따라가도 원래 질문을 유지하는가

- **목적 / 회장 질문:** 업무·실행·파일·대화를 확인한 뒤 원래 판단 대상으로 바로 돌아갈 수 있는가?
- **자료·근거:** 선택한 회사/환경·업무·구성원·실행·revision·필터·스크롤과 출발 화면의 허용된 참조를 유지한다.
- **표현·배치:** 공통 상세 패널 하나에서 내용을 교체한다. `Back to work`처럼 돌아갈 대상을 표시하고 겹친 패널을 쌓지 않는다.
- **행동:** 좁은 창에서도 닫기·한 단계 뒤로·고정 제어에 접근한다. 대화 입력의 참조는 보내기 전에 확인하고 제거할 수 있다.
- **상태:** 원본 접근이 사라지면 `Access restricted`를 표시한다. 창 닫기나 화면 이동이 외부 회사 운영의 정지를 뜻하지 않는다.
- **검증:** 1440×900/1100×720, light/dark, 키보드 선택·Escape 한 단계 닫기·포커스 복귀를 확인한다. 투자에서 왔다면 계좌·기간도 유지한다.
