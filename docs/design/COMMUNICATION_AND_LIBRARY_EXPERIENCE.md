# Conversations · Library: 목적과 행동 설계

상태: **v3 로컬 화면 구현 / 제품 연결·전체 인수 미완료**. 설명은 한국어, 실제 UI 문구는 영어로 작성한다.
방별 초안·문맥 이동과 고정 revision 탐색은 시안에 구현했다. 최신 범위는 [현재 coverage](UI_PURPOSE_CONTRACT.md#coverage),
검증은 v3 QA (retained local evidence; excluded from product Git)에 기록한다. 본문의 이전 시안 평가는
설계 당시 감사이며, 로컬 화면 구현은 실제 전달·게시 동작의 완료 증거가 아니다.
이 문서는 기존 계약을 화면에 투영한다. 새 API·DB·보고 서비스·위임·자동 실행 권한을 만들지 않는다.

## 기준과 공통 문법

- 제품 기준: [Mac 앱 계획](../implementation/MAC_APP.md#하나의-대화-기능과-별도의-관찰-화면).
- 화면 기준: [Rooms](../architecture/APPLICATION_SHELL_AND_VIEWS.md#rooms--who-do-i-need-to-talk-with-and-about-what), [Library](../architecture/APPLICATION_SHELL_AND_VIEWS.md#library--what-did-the-company-rely-on-and-produce), [공통 상세](../architecture/APPLICATION_SHELL_AND_VIEWS.md#shared-inspector-conversations-and-notifications).
- 기록 기준: [통합 대화 계약](../architecture/CONTRACTS_AND_STATE.md#unified-rooms-and-proactive-messages). 자료는 기존 Gateway·Catalog의 접근·게시·revision 계약을 따른다.
- 시각·조작은 [공통 primitives](./UI_PURPOSE_CONTRACT.md#primitives), 상태는 [shared states](./UI_PURPOSE_CONTRACT.md#shared-states)를 사용한다.
- OpenBoa의 전체 서체 역할과 Mira 컴포넌트를 유지한다. 제목은 현재 대상을, 본문은 내용을, 메타는 출처·시각을 구분한다. 누락·권한 제한처럼 판단을 바꾸는 정보는 메타 색으로 숨기지 않는다.
- 버튼은 실행할 행동, 탭은 같은 대상의 보기, 배지는 관측 상태를 나타낸다. 숫자 배지의 집계 의미를 이름 붙이고, 화살표·파일 아이콘에 다른 동작을 중복 부여하지 않는다.
- 공통 앱은 개인·그룹·에이전트 간 대화와 자료 탐색을 제공한다. 투자 참조는 도메인의 이름·관측 의미를 그대로 전달하며 공통 화면이 금융 값을 계산하지 않는다.

## Conversations 배치와 사용 흐름

회장의 질문은 “누구와 무슨 사안을 이야기하며, 전달·답변이 어디까지 됐고, 근거는 무엇인가?”이다.
왼쪽 방 목록 → 선택한 대화의 헤더·메시지·입력창 → 필요할 때만 공통 상세 패널 순서로 배치한다.
개인·그룹·에이전트 간 대화를 별도 앱이나 제출함으로 나누지 않는다. 읽기는 모델 호출이나 새 실행의 원인이 아니다.
1440×900에서는 방 목록과 대화를 함께 읽고, 1100×720에서 상세가 겹쳐 열려도 닫기·복귀·고정 제어를 유지한다.
표시 공간이 부족하면 방 목록을 접고 `Back to conversations`로 돌아간다. 입력창과 상세 패널을 겹겹이 쌓지 않는다.

<a id="r-01"></a>
### R-01 · 방 목록과 현재 선택

- 목적 / 회장 질문: 대화의 상대와 사안을 찾는다. “어느 방에 이미 이 이야기가 있는가?”
- 자료 근거: 읽기 가능한 기존 방, 참여자 이름, 주제·업무 참조, 최근 메시지와 제공된 읽기 위치.
- 배치 이유: 왼쪽 탐색 목록에 참여자·주제부터 보이고 최근 메시지·시각을 보조행으로 둬 대화 본문과 경쟁하지 않는다.
- 행동: 행을 선택하면 같은 방을 열고 읽던 위치를 복원한다. `CEO` 바로가기도 기존 방을 찾으며 클릭마다 방을 만들지 않는다.
- 상태: `Unread`와 `Awaiting reply`를 구분한다. 숫자는 해당 방의 제공된 기준을 쓰며 읽지 않음이 업무 차단을 뜻하지 않는다.
- 검증 기준: 같은 사안 재진입 시 방·메시지가 늘지 않고, 개인·그룹·에이전트 간 방을 같은 목록에서 찾는다.

<a id="r-02"></a>
### R-02 · 방 검색과 필터

- 목적 / 회장 질문: 이름을 외우지 않고 대상을 좁힌다. “이 업무를 논의한 사람·방은 어디인가?”
- 자료 근거: 허용된 방 이름·참여자·연결 업무의 검색 범위와 결과 범위; 미조회 영역은 포함됐다고 주장하지 않는다.
- 배치 이유: 목록 위 `Search conversations`와 참여자·업무 필터를 둔다. 개인/그룹 형식은 보조 필터다.
- 행동: 검색·필터·`Clear filters`가 목록만 바꾼다. 선택 방이 결과에서 빠져도 현재 대화를 닫지 않는다.
- 상태: `No matching conversations`, 접근 제한, 조회 실패, 검색 범위 미지원은 서로 다르게 표시한다.
- 검증 기준: 필터를 지우면 기존 목록·선택이 복원되고, 결과 없음이 대화 삭제로 읽히지 않는다.

<a id="r-03"></a>
### R-03 · 선택한 방 헤더와 수신 범위

- 목적 / 회장 질문: 말하기 전에 대상을 확인한다. “누가 이 내용을 볼 수 있고 실제 전달 대상은 누구인가?”
- 자료 근거: 현재 방·참여 기록, 업무 범위, 현재 책임 배정과 제공된 전달 대상; 참여자 신원은 인증 기록에서 온다.
- 배치 이유: 메시지 바로 위에 주제·읽기 가능한 참여자 이름·`Participants`를 둔다. 긴 명단은 상세로 펼친다.
- 행동: 참여자 상세와 관련 업무를 연다. 수신자는 기존 계약으로 결정하며 UI가 임의의 수신자 선택 기능을 만들어내지 않는다.
- 상태: `No CEO assigned`, `Recipient unavailable`, 변경된 참여·책임 배정을 표시한다. 참조 첨부가 새 접근 권한을 주지 않는다.
- 검증 기준: 전송 전 실제 수신 범위를 설명할 수 있고, 책임자 교체 후 기존 메시지를 다른 사람에게 조용히 재전달하지 않는다.

<a id="r-04"></a>
### R-04 · 메시지 본문과 작성자

- 목적 / 회장 질문: 설명의 주체와 맥락을 읽는다. “누가 무엇을 보고 이렇게 말했는가?”
- 자료 근거: 인증된 작성자·메시지 시각·답변 관계·첨부 참조. 실행 연결이 없으면 추정해서 붙이지 않는다.
- 배치 이유: 본문을 중앙의 주 읽기 영역으로 두고 작성자·시각·답변 대상을 가까이 둔다. 매 도구 이벤트를 채팅으로 복제하지 않는다.
- 행동: 원래 질문으로 이동하고 긴 자료는 파일 참조로 연다. 설명·진행 공유·제안은 같은 메시지이며 별도 제출 양식이 없다.
- 상태: 에이전트의 설명과 확인된 사실을 구분한다. `No reply yet`를 실행 실패나 업무 미완료로 자동 해석하지 않는다.
- 검증 기준: 에이전트끼리 먼저 말한 기록도 원래 작성자와 함께 읽고, 한 답변이 모든 참여자의 답변으로 표시되지 않는다.

<a id="r-05"></a>
### R-05 · 저장·전달·답변 상태

- 목적 / 회장 질문: 발송 결과를 과장 없이 확인한다. “저장만 됐는가, 대상에게 전달됐는가, 실제 답변이 왔는가?”
- 자료 근거: 저장 결과, 메시지별 고정 수신자 기록, 수신자별 전달 intent·관측, 실제 `reply_to` 메시지.
- 배치 이유: 해당 메시지 아래 `Stored`·전달 요약을 두고 선택하면 수신자별 상세를 연다. 세 단계를 단일 성공 체크로 합치지 않는다.
- 행동: `Delivery details`로 원래 요청의 상태를 조회한다. 접수 불명확 상태에서 자동 재전송·새 요청 생성은 하지 않는다.
- 상태: `Not delivered`, `Delivery pending`, `Delivery unconfirmed`, `Delivery failed`, `Reply received`를 증거대로 사용한다. 읽음은 전달 영수증이 아니다.
- 검증 기준: 저장 성공·전달 미지원, 일부 수신자만 전달, 접수 후 무답변, 중복 이벤트가 각각 다른 결과로 남는다.

<a id="r-06"></a>
### R-06 · 단일 입력창과 문맥 참조

- 목적 / 회장 질문: 사안을 다시 설명하지 않고 의사를 전달한다. “이 대상에 관해 무엇을 묻거나 제안할 것인가?”
- 자료 근거: 선택 방·현재 수신 범위, 작성 중인 텍스트, 업무/실행/event/투자 대상 또는 고정 파일 참조.
- 배치 이유: 입력창은 선택 대화 아래 하나만 둔다. `Replying to`·대상 칩·수신 범위를 전송 전에 같은 위치에서 확인한다.
- 행동: 문맥 칩을 미리보거나 제거하고 `Send`한다. 문서 연결은 지원되는 참조만 사용하며 파일 업로드·게시를 완료한 척하지 않는다.
- 상태: `Draft`, `Sending`, 저장 실패, 접근 제한, 전달 미지원과 답변 대기를 구분한다. 초안은 회사의 저장 메시지로 표시하지 않는다.
- 검증 기준: 한글 조합 중 Enter로 발송되지 않고, 중복 클릭·재연결이 동일 메시지를 복제하지 않으며 참조한 revision이 유지된다.

<a id="r-07"></a>
### R-07 · 메시지의 답장·근거·결정 행동

- 목적 / 회장 질문: 설명에서 근거 또는 정확한 개입으로 간다. “답변·원본 확인·권한 결정 중 무엇이 필요한가?”
- 자료 근거: 원래 메시지, 업무·Trace·아티팩트 참조, 존재하는 공식 결정의 정확한 대상·버전.
- 배치 이유: `Reply`·`View source`는 메시지 가까이에, 실제 결정 링크는 해당 문맥 안에 둔다. 버튼 수를 늘리는 일반 승인 툴바는 없다.
- 행동: 답장·원본 미리보기·메시지 검색 위치 이동을 제공한다. `Review decision`은 공통 고정 제어의 동일 기록을 연다.
- 상태: 없는 원본·철회된 접근·오래된 결정은 이유를 표시한다. 대화의 `approve` 문구나 읽음 처리로 권한·미결 상태가 바뀌지 않는다.
- 검증 기준: 모델이 쓴 승인 문장·가짜 버튼·파일 안 링크로 제어되지 않고, 정식 결정 상세에는 원래 버전이 표시된다.

<a id="r-08"></a>
### R-08 · 참여자와 방 정보 상세

- 목적 / 회장 질문: 책임과 대화 범위를 확인한다. “누가 참여하며 이 방은 어느 업무에 속하는가?”
- 자료 근거: 현재 참여 기록과 책임 배정, 허용된 업무 참조. 표시 이름과 실제 식별자의 연결은 진단에서 확인한다.
- 배치 이유: `Participants`로 공통 상세를 교체해 열고 메시지 본문에는 긴 명단·식별자를 반복하지 않는다.
- 행동: 참여자의 회사 운영 상세·관련 업무로 간다. 참여 변경은 현재 권한과 지원되는 명시적 기능이 있을 때만 제공한다.
- 상태: 제외된 참여자·이전 책임자·현재 참여자를 구분하며 재가입이 이전 미전달 메시지의 수신 권리를 복원하지 않는다.
- 검증 기준: 방 참여가 자원 권한·실행 할당으로 표시되지 않고, 명단을 보는 것만으로 참여·위임이 변경되지 않는다.

<a id="r-09"></a>
### R-09 · 문맥 대화와 원래 화면 복귀

- 목적 / 회장 질문: 조사 흐름을 이어간다. “방금 보던 대상에 관해 묻고 같은 위치로 돌아갈 수 있는가?”
- 자료 근거: 원래 화면·계좌·기간·업무·선택 대상·파일 revision, 방·읽기 위치·초안 참조.
- 배치 이유: 공통 상세 안 대화도 같은 방의 다른 보기다. 상단에 `Back`과 `Return to BTCUSDT position`처럼 출발 대상을 표시한다.
- 행동: 본문 대화로 넓히거나 파일·업무 상세로 교체하고 돌아온다. 패널을 여러 겹 쌓거나 별도 메시지 사본을 만들지 않는다.
- 상태: 출발 자료가 사라지거나 접근이 철회되면 해당 사실과 가능한 원래 목록 복귀를 제공한다.
- 검증 기준: 포지션→업무→파일→대화→복귀 후 계좌·기간·선택·스크롤과 초안이 유지되고 키보드 포커스가 출발 요소로 돌아온다.

<a id="r-10"></a>
### R-10 · 새 소식·읽기 위치·조회 상태

- 목적 / 회장 질문: 변화는 놓치지 않되 읽기를 방해받지 않는다. “새 소식인가, 내가 보던 위치 이후의 내용인가?”
- 자료 근거: 제공된 메시지 순서·cursor·조회 범위·읽기 위치와 누락 정보. 서버가 제공하지 않는 읽음 영수증은 추정하지 않는다.
- 배치 이유: 과거를 읽는 동안 `New messages`를 하단에 표시하고 자동으로 맨 아래로 이동시키지 않는다. 오류는 영향 받는 영역에 둔다.
- 행동: 새 메시지로 이동·이전 내용 불러오기·원래 요청 상태 재조회를 한다. 다시 여는 것만으로 에이전트를 깨우지 않는다.
- 상태: 빈 방, 수신자 없음, 연결 끊김, 일부 기록 누락, 로딩을 구분하고 마지막 조회 시각을 유지한다.
- 검증 기준: 여러 에이전트의 연속 메시지에도 읽던 위치를 보존하고, 읽지 않음·무응답이 정상 자율 업무를 멈추지 않는다.

<a id="r-11"></a>
### R-11 · 대화 시작

- 목적 / 회장 질문: 기존 방이 없을 때만 필요한 대화를 연다. “누구와 어떤 업무 범위에서 새 이야기를 시작할 것인가?”
- 자료 근거: 현재 허용된 기존 사람·에이전트·업무와 지원되는 방 생성 범위. 새 조직·에이전트·위임을 만들지 않는다.
- 배치 이유: `New conversation`은 방 목록의 보조 행동이다. CEO 기존 방과 검색보다 회사를 움직이는 필수 경로로 강조하지 않는다.
- 행동: 기존 방 일치를 먼저 확인하고, 허용된 범위를 선택해 명시적으로 생성한다. 지원되지 않는 개인/그룹 조합은 가능하다고 표시하지 않는다.
- 상태: 생성 중·이미 존재·권한 없음·해당 범위 미지원·수신자 없음이 구분된다. 방 생성 성공은 실행 시작이나 전달 성공이 아니다.
- 검증 기준: 반복 클릭으로 같은 목적의 방이 생기지 않고, 생성만으로 세션·권한·자원 할당이 발생하지 않는다.

## Library 배치와 사용 흐름

회장의 질문은 “무엇을 근거로 판단했고, 무엇이 실제로 만들어졌으며, 어느 버전이 사용됐는가?”이다.
상단 검색·범위 → 목적이 보이는 자료 목록 → 선택 파일의 공통 미리보기 순서이며 첫 행동은 `Preview`다.
목록은 결과물만이 아니라 허용된 입력 자료도 포함한다. 보고서·코드·데이터를 형식별 새 화면으로 나누지 않는다.
좁은 창에서는 미리보기가 겹쳐 열려도 목록 검색·필터·선택을 보존하고, 긴 내용만 본문 안에서 넓혀 본다.

<a id="a-01"></a>
### A-01 · 자료실 범위와 검색

- 목적 / 회장 질문: 필요한 근거를 찾는다. “회사에 어떤 자료가 있고 내가 확인할 수 있는 범위는 어디까지인가?”
- 자료 근거: 허용된 Catalog 목록·지원되는 작업 자료 원본, 조회 범위·시각·누락 상태. 회사 기록을 억지로 파일로 만들지 않는다.
- 배치 이유: `Library`와 `Search materials`를 위에 두고 최근 관련 자료를 기본 목록으로 보여준다. 검색은 원래 파일명을 유지한다.
- 행동: 이름·경로·지원되는 메타 필드로 검색한다. 본문 검색을 지원하지 않으면 `Names and metadata`처럼 범위를 명시한다.
- 상태: `No materials yet`, `No matching materials`, 일부 조회, 접근 제한, 서비스 실패를 구분한다.
- 검증 기준: 원래 파일명과 관련 업무로 찾을 수 있고, 부분 결과를 회사 전체 자료로 표시하지 않는다.

<a id="a-02"></a>
### A-02 · 자료 필터와 정렬

- 목적 / 회장 질문: 읽어야 할 자료를 좁힌다. “이 업무·작성자·기간에 해당하는 근거는 무엇인가?”
- 자료 근거: 작성자, 관련 업무, 종류, 관측된 게시 시각·상태와 지원되는 정렬 필드.
- 배치 이유: 검색 아래 한 줄의 필터를 두고 활성 조건을 보이게 한다. UUID·인증서 경로를 입력하는 기본 경험은 없다.
- 행동: `Author`, `Work`, `Type`, `Period`를 조합하고 `Clear filters`로 복원한다. 필터가 권한이나 보존 정책을 바꾸지 않는다.
- 상태: 선택 조건·결과 수·집계 범위를 연결하고 정확한 전체 수를 모르면 추정 합계를 표시하지 않는다.
- 검증 기준: 필터 후 파일을 보고 돌아오면 조건·정렬·스크롤이 유지되고, 결과 없음의 원인을 조건과 구분한다.

<a id="a-03"></a>
### A-03 · 자료 목록 행

- 목적 / 회장 질문: 내용을 열기 전에 관련성을 판단한다. “이 자료는 왜 생겼고 어떤 판단에 쓰였는가?”
- 자료 근거: 원래 이름·종류·작성자·생성/사용 업무·workspace·고정 revision·게시 시각·크기·실제 상태.
- 배치 이유: 이름과 목적/업무를 첫 열에, 버전·상태를 같은 행에 둔다. 식별자는 진단으로 펼치되 revision은 감추지 않는다.
- 행동: 행 선택·Enter는 미리보기를 연다. 작성자·업무 링크는 각각의 명확한 대상 상세를 열고 복귀 위치를 남긴다.
- 상태: `Working`, `Uploaded`, `Published`를 구분하며 최신 보존 버전과 현재 적용 중인 버전을 동일시하지 않는다.
- 검증 기준: 동일 파일명의 다른 workspace/revision을 구별하고, 업로드만 된 파일을 게시 완료 자료로 표시하지 않는다.

<a id="a-04"></a>
### A-04 · 파일 상세 헤더와 고정 정체성

- 목적 / 회장 질문: 보고 있는 원본을 확정한다. “어느 저장 공간의 어떤 버전을 읽고 있는가?”
- 자료 근거: 정확한 `workspace + revision + path`, 게시 시각, 작성자·파일 크기와 현재 조회 결과.
- 배치 이유: 미리보기 위에 이름·revision·관련 업무와 출발 문맥을 둔다. 긴 경로·해시는 `Details`에서 복사한다.
- 행동: `Copy reference`, 상세 펼치기, 이름 붙은 복귀를 제공한다. 최신 버전이 생겨도 선택 파일의 내용을 자동 교체하지 않는다.
- 상태: `Newer revision available`은 선택 변경 안내이며 현재 파일이 무효라는 판정이 아니다. 존재하지 않는 과거 버전은 명시한다.
- 검증 기준: 새 manifest가 게시돼도 열린 과거 자료의 참조·내용·대화 첨부가 같은 revision을 가리킨다.

<a id="a-05"></a>
### A-05 · 내용 미리보기

- 목적 / 회장 질문: 파일 이름이나 에이전트의 주장 대신 내용을 확인한다. “실제로 무엇이 기록돼 있는가?”
- 자료 근거: Gateway로 읽은 해당 revision의 실제 파일 내용과 지원되는 보기 형식·크기 제한.
- 배치 이유: 내용이 상세의 주 영역이다. 텍스트/Markdown·JSON·제한된 CSV/표·이미지·지원 문서는 자료에 맞는 보기로 표시한다.
- 행동: 문서 페이지·표 구간·검색 결과 위치로 이동하고 긴 내용은 `Expand preview`로 넓힌다. 코드·보고서 스크립트를 실행하지 않는다.
- 상태: 로딩·부분 내용·미지원 형식·해석 실패를 구분한다. 잘린 표·텍스트는 범위와 전체 확인 경로를 남긴다.
- 검증 기준: 원본과 보이는 값이 일치하고, 부분 미리보기를 전체 자료로 오인하지 않으며 이미지·문서 안 명령이 실행되지 않는다.

<a id="a-06"></a>
### A-06 · 파일 저장과 참조 행동

- 목적 / 회장 질문: 확인한 원본을 보관하거나 정확히 가리킨다. “이 버전을 내 Mac에 저장하거나 다른 기록에서 참조할 수 있는가?”
- 자료 근거: 현재 읽기·저장 가능 범위와 선택한 고정 파일 참조. 저장된 로컬 사본은 회사의 원장이 아니다.
- 배치 이유: `Save copy`·`Copy reference`는 미리보기 도구 영역에 둔다. 실행·활성화 버튼처럼 표현하지 않는다.
- 행동: 허용된 사본 저장·참조 복사만 수행한다. 저장이 재게시·덮어쓰기·코드 적용·외부 공유로 이어지지 않는다.
- 상태: 저장 요청·완료·취소·실패·접근 철회를 구분하고 완료한 파일명·위치를 확인한다.
- 검증 기준: 다운로드 내용과 선택 revision이 같고, 취소 시 완료 알림이 없으며 미지원 저장 기능을 동작한다고 표시하지 않는다.

<a id="a-07"></a>
### A-07 · 수정 이력과 버전 선택

- 목적 / 회장 질문: 변경의 연속성을 확인한다. “무엇이 언제 바뀌었고 당시에는 무엇을 읽었는가?”
- 자료 근거: 보존된 revision·작성/게시 기록·지원되는 변경 연결. 임시 파일의 존재를 내구성 있는 이력으로 만들지 않는다.
- 배치 이유: 선택 파일의 `Versions` 보기에 현재 선택·이전·최신 보존 버전을 시간순으로 둔다. 새 전체 메뉴는 만들지 않는다.
- 행동: 특정 버전을 열거나 비교 대상으로 고정한다. `Open latest`는 명시적 선택이며 과거 링크를 최신 manifest에서 다시 찾지 않는다.
- 상태: 게시됨·검증됨·적용됨을 별도 기록으로 표시하고, 과거 버전 미보존·삭제·접근 제한은 각각 설명한다.
- 검증 기준: 이전 버전을 선택하면 헤더·내용·참조가 함께 바뀌며, 같은 파일명이란 이유로 최신 내용을 대신 보여주지 않는다.

<a id="a-08"></a>
### A-08 · 변경 비교

- 목적 / 회장 질문: 수정이 판단에 미치는 영향을 읽는다. “두 버전에서 실제로 달라진 부분은 무엇인가?”
- 자료 근거: 선택한 두 고정 revision의 지원되는 텍스트 내용. 모델의 변경 설명은 실제 diff와 분리된 출처다.
- 배치 이유: `Compare` 안에 `From`·`To` 버전을 고정 표시한다. 좁은 창에서는 나란한 열 대신 순차 diff로 읽는다.
- 행동: 변경 위치 이동·전체 문맥 펼치기·각 원본 열기를 제공한다. 비교 화면에서 편집·수락·활성화를 암묵적으로 수행하지 않는다.
- 상태: 추가·삭제를 색과 `+`/`−`·문구로 함께 표시하고, 비교 불가·동일 내용·부분 비교·원본 누락을 구분한다.
- 검증 기준: 비교 방향과 버전을 바꿔도 원본 참조가 유지되고, 변경 없음과 비교 미지원이 같은 빈 화면이 되지 않는다.

<a id="a-09"></a>
### A-09 · 게시·검증·실제 적용 근거

- 목적 / 회장 질문: 만들어졌다는 주장과 확인된 결과를 구분한다. “게시됐는가, 검증됐는가, 실제로 사용됐는가?”
- 자료 근거: 게시 영수증·revision 재조회, 관련 도구/Trace, 기술 검증·수락·활성화·실제 적용 관측 중 존재하는 기록.
- 배치 이유: `Evidence`에 상태별 근거·시각을 나란히 연결한다. 모든 파일이 거쳐야 할 단일 진행률이나 승인 절차로 만들지 않는다.
- 행동: 각각의 영수증·실행·검증 결과·공식 결정 원본을 연다. 파일 설명의 `approved` 문장을 수락 기록으로 사용하지 않는다.
- 상태: `Not observed`, `Pending`, 확인된 결과, 불일치와 해당 없음의 근거를 표시한다. 실행 종료가 파일 게시 증거는 아니다.
- 검증 기준: 게시만 성공한 파일에 검증·활성화 완료가 붙지 않고, 실제 영수증과 작성자의 설명이 다르면 함께 확인할 수 있다.

<a id="a-10"></a>
### A-10 · 생성·사용 업무와 실행 근거

- 목적 / 회장 질문: 자료를 업무의 결과와 연결한다. “누가 왜 만들었고 다음 판단에서 어떻게 사용했는가?”
- 자료 근거: 기록된 생성 업무·실행·작성자, 입력 사용·참조 관계와 관련 Trace. 제목 유사성으로 사용 관계를 추정하지 않는다.
- 배치 이유: `Related work`에서 `Produced by`·`Used by`를 구분한다. 전체 실행 이력·Trace는 Company의 기존 보기로 이어진다.
- 행동: 담당 업무·실행·선택 도구 이벤트를 열고 해당 파일로 돌아온다. 자료실이 별도 실행 모니터나 업무 생성기가 되지 않는다.
- 상태: 참조됨·실제 사용 관측·사용 미확인을 구분하고, 관계 없음·일부 조회·접근 제한을 표시한다.
- 검증 기준: 파일→생성 실행→Trace→파일과 업무→입력 자료의 양방향 이동에서 같은 원본과 선택을 유지한다.

<a id="a-11"></a>
### A-11 · 자료에 관한 대화

- 목적 / 회장 질문: 원본을 붙여 설명을 요청한다. “이 버전의 근거나 변경 이유를 누구에게 물을 것인가?”
- 자료 근거: 선택 파일의 고정 참조, 작성자·담당 업무, 현재 허용된 기존 방과 실제 수신 범위.
- 배치 이유: `Ask about this file`은 미리보기의 보조 행동이며 파일 직접 확인·저장을 대신하지 않는다.
- 행동: 기존 CEO/구성원/그룹 대화를 열고 파일 칩을 입력창에 붙인다. 같은 클릭으로 메시지 전송이나 새 방 생성을 하지 않는다.
- 상태: 작성자 부재·현재 책임 변경·수신자 접근 제한을 표시한다. 읽을 권한 없는 상대에게 참조 첨부만으로 권한을 부여하지 않는다.
- 검증 기준: 답변과 파일 원본이 같은 revision으로 연결되고, 돌아오면 미리보기 위치·버전·목록 필터가 보존된다.

<a id="a-12"></a>
### A-12 · 누락·실패·작업 자료의 경계

- 목적 / 회장 질문: 자료가 없는 이유와 다음 가능한 행동을 판단한다. “없어진 것인가, 못 읽는 것인가, 아직 게시되지 않은 것인가?”
- 자료 근거: 해당 요청의 현재 권한·원본 서비스 결과·revision 보존·게시 관측. 임의 로컬 경로나 컨테이너 파일을 대신 읽지 않는다.
- 배치 이유: 실패한 미리보기 위치에 원인·원본 참조·가능한 행동을 남기고 전체 앱이나 고정 제어를 오류로 덮지 않는다.
- 행동: 허용된 원래 참조 재조회·목록 복귀·지원되는 사본 저장을 제공한다. 미확정 요청을 새 게시나 복구 작업으로 자동 전환하지 않는다.
- 상태: `Preview unavailable`, `Access restricted`, `Content deleted`, `Revision unavailable`, `Unpublished`를 구분한다. 파일명으로 내용을 만들어내지 않는다.
- 검증 기준: 접근 철회·삭제·과거 revision 부재·미지원 문서를 각각 확인하고, 작업 파일은 지원되는 허가된 원본이 있을 때만 보인다.

## 연결 검증과 완료 보고

- R/A 식별자는 화면·컴포넌트·검증 기록에서 같은 목적을 가리키는 추적 참조이며 새 제품 record ID가 아니다.
- 검증은 **설계 명세 / 개발 데이터 화면 / 실제 서비스 연결 / 실제 결과 확인**을 각각 기록한다. 한 상태를 다른 상태의 완료로 보고하지 않는다.
- 대화 인수: 개인·그룹·에이전트 간 같은 창구, 저장만 성공, 수신자별 전달, 실제 답변, 책임 교체, 재연결 중복 방지, 권한 철회.
- 자료 인수: 원본 미리보기, 정확한 이전 revision 재조회, 비교 가능/불가, 게시 영수증, 설명과 검증 불일치, 허가된 사본 저장.
- 문맥 인수: 투자 대상→업무→파일→대화→출발 위치를 1440×900/1100×720에서 이동하고 선택·스크롤·키보드 포커스 복귀를 확인한다.
- 공통 인수: 두 테마, 긴 이름·금액, 한글 입력, 화면 낭독용 행동 이름, 키보드·Escape, 빈 상태·부분 조회·실패를 확인한다.
- 문서와 정적 시안만으로 이 검증들은 통과하지 않는다. 실제 구현이 없는 경로는 `Not implemented`, 실행하지 않은 검증은 `Not run`으로 남긴다.
