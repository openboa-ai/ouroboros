# Portfolio Experience — 회장의 투자 정보와 행동

이 문서는 Portfolio와 그 상세 화면의 목적을 정의한다. [화면 아키텍처](../architecture/APPLICATION_SHELL_AND_VIEWS.md#investment-and-performance--should-i-continue-entrusting-capital)와 [Mac 작업 기록](../implementation/MAC_APP.md)을 따른다.
회장의 질문은 **지금 얼마가 있는가 → 선택 기간에 무엇이 달라졌는가 → 현재 무엇을 보유하고 있는가 → 왜 그렇게 운용하며 무엇을 확인하거나 논의할 것인가**다.
금융 계산·위험 기준·한도·권한·서비스를 새로 정하지 않는다. 필요한 근거가 없으면 해당 정보를 미확인으로 표시하며, 근거 생산을 이 문서의 구현 완료로 간주하지 않는다.

v3에서 이 계약을 기준으로 투자 화면과 연결된 상세를 재설계했다.
아래 `v2` 상태 평가는 당시 감사 기록이며, 최신 구현 범위는 [공통 계약의 coverage](UI_PURPOSE_CONTRACT.md#coverage),
관측 증거는 v3 QA (retained local evidence; excluded from product Git)를 따른다.

## 읽는 방법과 공통 규칙

- `P-01`부터 `P-22`는 코드 주석·검토 기록에서 사용하는 고정 요소 ID다. 요소 이동이나 이름 변경으로 ID를 재사용하지 않는다.
- `v2 있음`은 [디자인 캘리브레이션](../../design/mac-calibration/src/App.tsx)에 표시 또는 조작이 있다는 뜻이다. 실제 계정·실행 연결이나 전체 요구 충족을 뜻하지 않는다.
- `v2 개선`과 이 표의 `미구현`은 v2 감사 당시의 상태다. v3에서 개선한 범위는 위 coverage에 별도로 갱신한다.
- v2 화면 근거는 Portfolio 캡처 (retained local evidence; excluded from product Git)다. v2의 숫자·이름·시각은 예시이며 운용 기준이 아니다.
- 각 요소는 [공통 상태](./UI_PURPOSE_CONTRACT.md#shared-states)와 [공통 부품](./UI_PURPOSE_CONTRACT.md#primitives)을 사용한다. 아래에는 요소별 의미와 차이만 적는다.
- 본문의 화면 문구는 English로 유지한다. 숫자·부호·단위는 함께 읽히며, 색이나 아이콘만으로 금융 의미·자료 상태·행동을 전달하지 않는다.
- 기간은 손익·자금 이동·비용·추이에 적용한다. 현재 계정값·포지션·미체결 주문·CEO의 최근 판단은 각각 `Current`와 자기 관측/작성 시각을 유지한다.
- 상세는 선택한 계정·기간·기록·revision을 보존한다. 과거 기간을 선택했다고 현재 포지션을 과거 종가 포지션으로 바꾸지 않는다.

## Portfolio 본문

<a id="p-01"></a>
### P-01 — Portfolio의 읽기 순서와 배치
- **목적:** “지금 내 투자를 어떻게 이해해야 하는가?”에 먼저 답한다. 범위 → 현재 계정값/기간 결과 → 현재 노출·미체결 → 추이·실제 기록 → CEO 맥락 순서로 읽는다.
- **필요근거:** 아래 P-02~P-16의 같은 회사에 속한 관측과 명시적인 계정/기간 범위. 에이전트 실행 개수나 큰 시세 차트는 투자 결과를 대신하지 않는다.
- **표현:** `Portfolio` 아래 넓은 본문에 두 주요 값·추이·기록 행, 보조 열에 현재 노출·주문·짧은 CEO 설명을 둔다. 동일 크기 카드로 모든 정보를 동급 처리하지 않는다.
- **행동:** 주요 값·기록에서 상세로 들어간다. 첫 화면을 읽기 위해 대화·주문·업무 생성을 요구하지 않는다. 전체 앱 탐색과 제어는 공통 골격을 사용한다.
- **상태:** v2 있음/개선. 1440×900에서는 본문/보조 열을 병렬 배치한다. 좁은 잔여 폭에서는 [L-03](UI_PURPOSE_CONTRACT.md#l-03)에 따라 현재 노출·중요 주문을 차트보다 먼저 읽고 CEO 보조 문맥을 뒤로 보낸다. 보조 열 전체를 일괄 맨 아래로 밀지 않는다. 일부 조회 실패는 해당 영역에 남긴다.
- **판정기준:** 별도 설명 없이 현재값과 기간 결과를 구별하고 현재 포지션을 찾는다. 상세를 열어도 금액·단위가 잘리지 않으며 한 영역 실패가 나머지 정보를 가리지 않는다.

<a id="p-02"></a>
### P-02 — 회사·계정·계약·자료 환경
- **목적:** “어느 회사의 어느 계정과 계약을 보고 있는가?”를 숫자보다 먼저 식별한다. 이 문맥은 모든 후속 판단의 범위를 정한다.
- **필요근거:** 실제 회사/환경 연결, 계정 식별과 조회 범위, 계약 메타데이터, 자료의 실제/개발 출처. 회사명·거래소명만으로 계정 전체 범위를 추정하지 않는다.
- **표현:** `Portfolio`, `Binance USDⓈ-M`, `BTCUSDT perpetual`과 계정 범위를 구분한다. `Sample data`는 제품 소유 상태 태그다. 거래소/지갑 아이콘은 분류 보조이며 인증 완료 표시가 아니다.
- **행동:** 지원되는 계정/범위 선택과 연결 상세로 이동한다. 계약 필터를 바꿔도 계정 전체 잔고가 계약별 자본으로 재명명되지 않는다.
- **상태:** v2 있음/개선. 현재는 거래소·계약·샘플 표시가 있으나 구체적인 계정 범위 식별은 미완성이다. 미연결·권한 제한은 각각 구별한다.
- **판정기준:** 사용자가 계약 필터와 계정 잔고 범위를 구별한다. 회사/환경 변경 시 이전 자료가 새 계정 값처럼 남지 않는다.

<a id="p-03"></a>
### P-03 — Reporting period
- **목적:** “언제의 결과를 비교하는가?”를 정한다. 기간 선택은 날짜 장식이 아니라 결과·비용·자금 이동·추이를 함께 읽기 위한 기준이다.
- **필요근거:** 지원 기간, 시작/종료 시각과 시간대, 각 자료의 적용 가능 기간. 현재값의 별도 관측 시각도 유지한다.
- **표현:** `Reporting period`, `Sep 7–13, 2026`처럼 범위를 노출한다. 달력 아이콘은 기간 선택, chevron은 선택지 열기를 뜻한다. `7D`만으로 정확한 경계를 대신하지 않는다.
- **행동:** 기간을 바꾸면 기간 집계·차트·이력을 갱신한다. 이미 연 주문·판단·파일은 원래 시각·revision을 유지하며 새 기간 밖이면 그 사실을 표시한다. 현재 포지션·미체결 주문은 `Current`를 유지한다.
- **상태:** v2 있음/개선. 현재 선택지는 한 주뿐이며 다른 기간 조회는 없다. 제공할 기간이 하나면 기능이 없는 선택기를 확장 가능한 것처럼 꾸미지 않는다.
- **판정기준:** 기간 변경 후 손익·입출금·차트·거래이력이 같은 범위를 보이며, 현재 포지션의 시점과 혼동되지 않는다.

<a id="p-04"></a>
### P-04 — Account equity
- **목적:** “현재 이 계정의 평가액은 얼마인가?”에 답한다. 본문에서 가장 큰 값으로 두되 회사 전체 순자본이라는 의미를 임의로 부여하지 않는다.
- **필요근거:** 출처가 정의한 계정 평가값, 통화, 계정 범위, 관측 시각, 포함 자산/부채 범위. 회사 전체 집계가 없다면 계정 관측만 제시한다.
- **표현:** `Account equity`, 금액과 `USDT`, `Current · As of …`를 묶는다. 단위는 부속 장식이 아니며 생략하지 않는다. 금액 크기는 중요도를 나타내고 긍정 평가를 뜻하지 않는다.
- **행동:** 금액 또는 `View account`로 P-17을 연다. 상세는 현재 평가의 구성과 기간 시작/종료 관측이 있는 경우 그 차이를 읽게 한다.
- **상태:** v2 있음/개선. 현재 금액은 선택 불가하다. 미관측은 대시와 이유, 오래된 값은 실제 시각을 표시하고 새로 조회하는 동안 0으로 바꾸지 않는다.
- **판정기준:** `113,650.00 USDT` 같은 현재 수량을 기간 수익으로 읽지 않는다. 계정값을 선택해 출처와 포함 범위를 확인할 수 있다.

<a id="p-05"></a>
### P-05 — Trading P&L
- **목적:** “선택 기간의 거래 결과는 얼마이며 어떤 비용/손익을 포함하는가?”에 답한다. 현재 계정값 옆에 기간 결과로 배치한다.
- **필요근거:** 기간 손익의 출처·정의·시점, 실현/미실현 처리와 거래 수수료/펀딩 포함 범위, 제외한 회사 운영 비용. 없는 계산 정의를 화면이 정하지 않는다.
- **표현:** `Trading P&L · Sep 7–13`, 부호 있는 금액·단위, 실제 포함 범위를 짧게 표시한다. `Company operating costs excluded`는 해당할 때 유지하며 색만으로 이익/손실을 구별하지 않는다.
- **행동:** 금액 또는 `View P&L details`로 P-18을 열어 관련 체결·비용과 계산 근거를 확인한다. 제외한 운영비도 같은 상세의 출처 링크로 확인한다. 현재 미실현 손익을 여기에 별도로 더하지 않는다.
- **상태:** v2 있음/개선. 현재 미실현 `+360`과 기간 `+3,650`의 관계가 설명되지 않는다. 기간 정의/범위가 미확정이면 확정 집계처럼 표시하지 않는다.
- **판정기준:** 사용자가 기간 결과, 현재 미실현 값, 입금과 제외 비용을 구별한다. 손익 상승만으로 회사 수익성·AI 기여가 증명됐다고 표시하지 않는다.

<a id="p-06"></a>
### P-06 — Net deposits와 자금 이동 맥락
- **목적:** “계정 변화 중 내가 넣거나 꺼낸 자금은 무엇인가?”를 주요 금액 바로 아래에서 분리한다. 거래 성과로 오인할 여지를 줄이는 비교 정보다.
- **필요근거:** 선택 기간의 확인된 입금·출금과 출처 분류. 원금 반환/이익 인출의 성격은 근거가 있을 때만 구별한다.
- **표현:** `Net deposits · Sep 7–13`, 금액·단위와 `Excluded from trading P&L`을 표시한다. 방향 아이콘은 자금 이동 보조이며 거래 방향이나 수익 상태를 뜻하지 않는다.
- **행동:** 행을 선택하면 P-14의 해당 기간 자금 이동으로 이동한다. 날짜·금액·상태·출처를 확인하고 원래 주요 값으로 돌아온다.
- **상태:** v2 있음/개선. 현재 한 줄의 입금 요약은 클릭되지 않는다. 확인된 순이동 0과 일부 이력 미조회는 다르게 표시한다.
- **판정기준:** 입금이 있어 계정값이 오른 예시에서도 그 입금을 거래 이익으로 합산하지 않는다. 요약에서 실제 자금 이동 기록을 찾는다.

<a id="p-07"></a>
### P-07 — P&L / Equity 차트 모드
- **목적:** “거래 결과의 누적인가, 계정값의 이력인가?”를 차트 위에서 선택한다. 서로 다른 의미를 한 제목 아래 섞지 않는다.
- **필요근거:** 선택 기간과 범위가 명시된 두 시계열의 정의·존재 여부. 숫자가 있다는 이유만으로 같은 평가 기준을 갖는다고 가정하지 않는다.
- **표현:** 탭은 `P&L` / `Equity`, 제목은 `Trading P&L` / `Account equity history`로 따른다. 선택 표시와 보조 설명은 읽는 값의 의미를 알리는 용도다.
- **행동:** 탭은 계정·기간을 유지하며 제목·단위·축·툴팁·자금 이동 표시를 함께 바꾼다. 투자 기록 탭 P-11과 기능을 섞지 않는다.
- **상태:** v2 있음/개선. 모드 전환은 있지만 상단 `Performance` 제목은 고정이다. 한 시계열이 없으면 그 이유를 표시하며 다른 시계열로 대체하지 않는다.
- **판정기준:** `Equity`의 입금으로 생긴 변화를 거래 성과 곡선으로 읽지 않는다. 탭 선택을 키보드와 표시 상태로 확인한다.

<a id="p-08"></a>
### P-08 — 추이·축·관측점·자금 이동 표시
- **목적:** “언제 값이 바뀌었고 어느 기록을 더 볼 것인가?”를 넓은 본문에서 보여준다. 곡선의 미관보다 변화 탐색이 목적이다.
- **필요근거:** 실제 시계열 관측점·시간대·단위·공백, 확인된 입출금 사건, 선택점에서 연결 가능한 기록. 모양을 위해 중간 값을 만들지 않는다.
- **표현:** 축은 시간/금액 단위를, 선/점은 관측값을, 입금 마커는 실제 자금 이동을 뜻한다. 툴팁은 정확한 시각·지표명·금액·단위를 반복 확인시키며 마지막 점은 최신 관측이지 성과 인증이 아니다.
- **행동:** `Equity` 관측점은 P-17의 선택 시각 계정 관측, `P&L` 관측점은 P-18의 해당 지표·시점 근거, 자금 이동 마커는 P-14로 연다. 과거 점을 현재 계정값으로 대체하지 않는다. hover 외에 키보드 선택 또는 동등한 데이터 목록을 제공한다.
- **상태:** v2 있음/개선. 예시 선·툴팁·입금 마커는 있으나 근거 선택 경로는 미구현이다. 신뢰 가능한 이력이 없으면 현재값과 공백을 보여주고 가상 곡선을 그리지 않는다.
- **판정기준:** 현재 모드·단위·시점을 알며 변화에서 근거로 이동한다. 자료 공백은 선으로 메워지지 않고 확대/축 변경이 값의 의미를 바꾸지 않는다.

<a id="p-09"></a>
### P-09 — Current position / Exposure 요약
- **목적:** “현재 무엇을 얼마나 보유하고 있는가?”에 짧게 답한다. 기간 차트 옆에서 현재 상태임을 분리하며 과거 선택 기간의 보유량으로 오인하지 않게 한다.
- **필요근거:** 계정·계약·방향·체결된 현재 수량, 명목가치·증거금·미실현 값의 출처와 관측 시각. 주문 잔량은 P-10에서 분리한다.
- **표현:** `Current position` 아래 계약·방향·수량을 작은 식별 행으로, `Notional value`를 규모 비교의 주 값으로 둔다. `Position margin`·`Unrealized P&L`은 보조 값, 미체결은 P-10의 별도 행이다. 방향은 중립 태그로 표시하며 안전 평가가 아니다. 현재 수량을 본문과 보조 열의 큰 숫자로 반복하지 않는다.
- **행동:** `View position`과 상세 화살표로 P-19를 연다. 계정 전체 노출이 아닌 단일 포지션 요약을 `Total exposure`로 부르지 않는다.
- **상태:** v2 있음/개선. 기존 `Exposure`가 단일 포지션을 보여준다. 실제 포지션 없음은 정상 빈 상태이고, 미관측·부분 계정 범위는 별도 상태다.
- **판정기준:** 체결된 보유량과 미체결 주문량을 구별한다. 증거금을 최대 손실이나 허용 위험 한도로 해석하게 하는 미터·등급을 추가하지 않는다.

<a id="p-10"></a>
### P-10 — Open order 요약
- **목적:** “어떤 주문이 아직 열려 있고 무엇이 남았는가?”를 포지션 옆에서 확인한다. 일반 작업 완료율이 아니라 거래 상태를 요약한다.
- **필요근거:** 정확한 주문 참조, 방향, 주문 수량·체결 수량·남은 수량, 상태와 최신 관측. 체결과 취소가 경합하면 확인된 결과를 보존한다.
- **표현:** `Open buy order`, `Partially filled`, `Filled / Total`과 `Remaining` 수량·단위. 비율 막대는 같은 주문의 실제 체결/주문 수량일 때만 보조로 사용한다.
- **행동:** 요약 선택은 해당 주문이 선택된 P-20을 연다. 다른 주문이나 일반 포지션 상세로 대신 보내지 않는다.
- **상태:** v2 있음/개선. `50% filled`와 `0.05 / 0.10 BTC`는 있으나 상세 진입은 없다. 미확정 제출은 확정된 미체결 주문과 구별한다.
- **판정기준:** 남은 수량을 즉시 읽고 실제 주문/체결을 확인한다. 막대 100%를 회사 업무 완료나 위험 제거로 표현하지 않는다.

<a id="p-11"></a>
### P-11 — Positions / Open orders / Activity 탭
- **목적:** “현재 보유, 진행 주문, 기간 중 사건 가운데 무엇을 볼 것인가?”를 같은 계정 문맥 안에서 고른다. 상세 기록은 추이 아래에 둔다.
- **필요근거:** 현재 포지션/열린 주문의 관측 범위와 선택 기간 사건 목록. 개수에는 조회 범위와 누락 여부가 연결돼야 한다.
- **표현:** `Positions`, `Open orders`, `Activity`; 숫자 태그는 알려진 해당 집합의 개수다. 현재 두 탭에는 `Current`, 이력에는 선택 기간을 명시한다.
- **행동:** 선택한 탭과 행·스크롤을 보존한다. `View transactions`는 P-14의 기간/필터를 유지한 전체 이력으로 이어지는 보조 진입이다.
- **상태:** v2 있음/개선. 세 탭과 예시 개수는 있다. 부분 조회를 전체 0건으로, 이력 기간을 현재 포지션 시점으로 표시하지 않는다.
- **판정기준:** 탭을 바꿔도 계정이 바뀌지 않고 개수의 의미가 유지된다. 빈 목록에서도 조회 성공 여부와 시점을 알 수 있다.

<a id="p-12"></a>
### P-12 — Position 행
- **목적:** “어떤 계약의 현재 포지션을 자세히 볼 것인가?”를 비교 가능한 행으로 제공한다. 긴 해설보다 계약·방향·수량·가격·미실현 값을 우선한다.
- **필요근거:** 포지션 참조, 계약·계정·관측 시각, 출처가 제공하는 진입/기준 가격과 단위, 미실현 손익. 임의 청산 가격 계산은 없다.
- **표현:** `Contract`, `Position`, `Entry / Mark`, `Unrealized P&L`; 두 가격을 쌓으면 각 값에 `Entry`/`Mark`를 붙여 순서를 외우지 않게 한다. 지갑 아이콘은 계약 분류, chevron은 상세 열기를 나타낸다.
- **행동:** 행의 명확한 선택 영역/`Open position`으로 P-19를 연다. 보조 버튼이 있으면 행 전체 선택과 중복 작동하지 않는다.
- **상태:** v2 있음/개선. 현재 마지막 chevron만 상세를 연다. 가격 일부 누락은 해당 셀에 표시하고 유효 수량을 지우지 않는다.
- **판정기준:** 긴 계약명·작은 수량·음수 손익에도 단위와 부호가 남는다. 키보드로 같은 포지션 상세에 도달한다.

<a id="p-13"></a>
### P-13 — Open order 행
- **목적:** “어느 주문이 어떤 상태로 남아 있는가?”를 비교하고 정확한 주문을 고른다. 주문 접수와 체결을 구별하는 기본 목록이다.
- **필요근거:** 계정/계약, 주문 참조·방향·유형·가격이 있는 경우 그 값, 체결/주문 수량, 관측된 상태·시각. 외부 주문은 실제 출처를 유지한다.
- **표현:** `Contract / Side`, `Type`, `Filled / Total`, `Status`, 관측 시각. `Partially filled` 등의 태그는 공급자가 확인한 단계이며 자체 승인 표시가 아니다.
- **행동:** 해당 주문을 선택해 P-20의 주문 조건·실제 체결·관련 포지션을 읽는다. 주문마다 존재하는 판단/실행 참조만 제공한다.
- **상태:** v2 있음/개선. 표는 있으나 행 상세는 없다. 제출 결과 미확정, 일부 체결, 취소 확인을 하나의 완료 상태로 합치지 않는다.
- **판정기준:** 같은 계약의 여러 주문을 구별하고 정확한 주문의 체결을 연다. 모든 주문을 CEO가 만든 것으로 자동 귀속하지 않는다.

<a id="p-14"></a>
### P-14 — Activity / Transactions
- **목적:** “선택 기간에 실제로 무엇이 있었는가?”를 거래·비용·자금 이동 기록으로 확인한다. 독립 주 메뉴를 늘리지 않고 Portfolio에서 이어진다.
- **필요근거:** 사건 시각·출처·유형·금액/수량·단위·상태·고유 참조, 주문/체결/비용/자금 이동의 실제 관계. 같은 비용의 관측 단계는 별도 비용으로 더하지 않는다.
- **표현:** `Activity`, 상세 목록 `Transactions`; 행은 `Deposit`, `Fill`, `Fee`, `Funding` 등 실제 분류와 값을 표시한다. 아이콘·체크는 해당 사건 분류/확인 단계만 뜻한다.
- **행동:** 기간·유형으로 좁히고 사건에서 P-17/P-18/P-20의 출처를 연다. 관련 판단은 근거가 있을 때 P-21로 연결한다.
- **상태:** v2 일부 있음/미구현. 입금·부분 체결 예시 두 행만 있다. 전체 이력·필터·원본 이동은 미구현이며 보존 범위 밖 이력을 꾸미지 않는다.
- **판정기준:** 계정 증가를 입금과 거래 결과로 구별하고 원본을 찾는다. 단순 시간 인접성을 인과 관계로 그리지 않는다.

<a id="p-15"></a>
### P-15 — CEO context
- **목적:** “CEO는 현재 상태를 어떻게 판단하고 다음에 무엇을 확인하려는가?”에 짧게 답한다. 금융 관측 다음에 배치하며 긴 설명은 상세/대화에서 읽는다.
- **필요근거:** 실제 작성 구성원·당시 책임·판단 기록/revision·작성 시각·관련 포지션/주문, 기록된 다음 검토 조건. 설명과 실제 실행 관측은 별도 근거다.
- **표현:** `Latest view`, 구성원 이름·`CEO`·작성 시각, 한 문장 설명, `Next review condition`. 아바타는 지속 작성자 식별이고 직함은 권한/현재 실행의 증명이 아니다.
- **행동:** `View rationale`은 P-21, `Ask Atlas` 같은 실제 수신자 버튼은 P-22로 이어진다. 문구·화살표는 각각 근거 열기/질문 시작을 뜻한다.
- **상태:** v2 있음/개선. 현재 `Managing…`은 보고를 현재 동작처럼 보이게 한다. 미배정·보고 없음·오래된 판단·수신자 변경을 구별하고 관측 자료를 계속 읽게 한다.
- **판정기준:** 판단 작성 시각과 계정 관측 시각이 달라도 구별한다. `Next review` 문구만으로 실제 wake 등록이나 자동 실행을 주장하지 않는다.

<a id="p-16"></a>
### P-16 — 출처·시각·자료 상태
- **목적:** “이 정보는 어디서 언제 확인됐으며 현재 어느 범위까지 믿고 읽을 수 있는가?”를 짧게 확인한다. 중요한 수치와 분리된 장문의 면책문으로 대체하지 않는다.
- **필요근거:** 자료 그룹별 출처·관측/수신 시각·범위·공백·환경. 같은 시각/범위를 실제 공유하는 그룹에만 공통 출처 줄을 적용한다.
- **표현:** `Sample account records`, `As of …`, `Updated …`, `Partial coverage` 등 사실에 맞는 짧은 문구. 방패/체크 아이콘은 샘플의 실거래 검증이나 완전성을 암시하지 않는다.
- **행동:** 출처 상세는 해당 관측/연결 정보를 열고, 지원되는 `Refresh`는 재조회만 한다. 거래·실행 요청을 다시 보내지 않는다.
- **상태:** v2 있음/개선. 공통 하단 시각은 모든 다른 자료까지 최신으로 만들지 않는다. 갱신 중·오래됨·미연결·권한 제한은 공통 상태로 구별한다.
- **판정기준:** 작은 태그만 숨겨 실제 자료처럼 보이는 개발 모드가 없다. 핵심 누락·범위·단위는 hover 없이 읽히며 권한 철회 후 이전 표시를 계속 제공하지 않는다.

## 선택한 사실의 상세

<a id="p-17"></a>
### P-17 — Account details
- **목적:** “현재 계정값의 구성과 포함 범위는 무엇인가?”에 답한다. 상단 현재값/시각 → 출처별 구성 → 자금 이동/관측 이력 순서로 배치한다.
- **필요근거:** 같은 계정의 출처가 정의한 잔고·가용 금액·증거금·평가 범주와 시각, 포함/미포함 범위, 기간 시작/종료 관측이 있는 경우 그 기록.
- **표현:** `Account details`, `Account equity`, 공급자 의미를 보존한 각 항목·단위, `As of …`; 회사 전체 미집계는 범위 설명으로 남긴다. 상이한 관측 시점을 같은 구성 합계로 강제하지 않는다.
- **행동:** 구성/자금 이동에서 해당 출처와 P-14로 이동하고, `Ask CEO`에는 계정과 선택 관측/기간을 첨부한다. 닫으면 P-04의 위치로 돌아간다.
- **상태:** 미구현. 일부 구성 미조회 시 전체 평가액의 존재 여부와 별도로 표시한다. 과거 관측이 없으면 현재값으로 과거 값을 대신하지 않는다.
- **판정기준:** 계정 평가액과 회사 순자본·가용 잔고가 구별되며 각 숫자의 범위·시점·출처를 확인한다. 확인되지 않은 회사 합계를 새로 산출하지 않는다.

<a id="p-18"></a>
### P-18 — Trading P&L details
- **목적:** “기간 결과는 어떤 기록과 기준으로 나왔는가?”에 답한다. 기간/결과/포함 기준 → 확인된 구성과 비용 → 관련 사건/설명 순서로 배치한다.
- **필요근거:** 사용된 기간 계산의 출처·정의, 실현/미실현 처리, 수수료·펀딩·제외 운영비, 입력 범위·누락 및 관련 기록. 표준 수익률이나 새 배분 공식을 정하지 않는다.
- **표현:** `Trading P&L details`, 정확한 기간·통화, `Included` / `Excluded`와 정의된 구성. 현재 미실현 값이 필요하면 `Current unrealized P&L`로 기간 값과 분리한다.
- **행동:** 체결·거래 비용·자금 이동은 P-14/P-20, 실제 작성된 해석은 P-21로 연결한다. 제외된 모델·compute·데이터·소유자 부담 비용은 [O-15](COMPANY_EXPERIENCE.md#o-15) 또는 [N-04](UI_PURPOSE_CONTRACT.md#n-04)의 같은 기간·귀속 범위로 연다. 미조회·미가격 범위는 표시하고 새 회사 순이익을 계산하지 않는다. 차트 선택은 해당 관측 시각을 유지한다.
- **상태:** 미구현. 계산 정의·구성 자료가 없으면 해당 한계를 표시하고 추정 분해를 만들지 않는다. 불일치가 있으면 원래 값과 출처를 함께 보존한다.
- **판정기준:** 현재 미실현 값을 기간 결과에 두 번 더하지 않고, 출자나 인출을 거래 이익으로 처리하지 않는다. 거래 결과만으로 회사 전체 이익·AI 기여를 인증하지 않는다.

<a id="p-19"></a>
### P-19 — Position details
- **목적:** “이 포지션은 현재 어떤 상태이며 어떤 거래/판단과 이어지는가?”에 답한다. 보유량·가격·관측 → 주문/체결 → 판단/자료 순서로 읽는다.
- **필요근거:** 선택 포지션의 계정·계약·방향·수량·가격·평가·증거금과 시각, 실제 주문/체결 관계, 존재하는 판단/아티팩트 참조. 현재 자료와 과거 자료를 구별한다.
- **표현:** `Position details`, `Current`, `Entry price`, `Mark price`, `Position margin`, `Unrealized P&L`; 값마다 단위와 정의된 의미를 유지한다. 판단은 `Decision context`로 따로 묶는다.
- **행동:** 주문/체결은 P-20, 근거 문서는 정확한 revision, 판단은 P-21로 연다. 필요한 질문과 제공되는 제어는 P-22를 사용한다.
- **상태:** v2 일부 있음/개선. 현재 상세는 미실현 손익을 먼저 강조하며 관계 목록·실제 자료 링크는 없다. 포지션 종료와 이력 삭제를 구별한다.
- **판정기준:** 주문/체결에서 포지션까지 실제 관계만 추적하고, 다른 시점의 값이나 다른 계정으로 대체되지 않는다. 미실현 이익이 현재 노출을 가리지 않는다.

<a id="p-20"></a>
### P-20 — Order and fill details
- **목적:** “이 주문에 무엇을 요청했고 실제로 무엇이 체결/취소/미확정됐는가?”에 답한다. 현재 상태/잔량 → 주문 조건 → 시각별 체결·비용 → 관련 근거 순서다.
- **필요근거:** 고정 주문 참조, 요청 조건·전송 시도·거래소 관측, 각 체결 참조·수량·가격·비용·시각, 현재 잔량/상태와 관련 포지션. 없는 외부/수동 주문의 에이전트 귀속을 만들지 않는다.
- **표현:** `Order details`, `Requested`, `Filled`, `Remaining`, `Fills`, `Last observed`; 상태 태그는 요청 접수/부분 체결/취소 확인/결과 미확정을 구별한다. 진단 ID는 복사 가능한 보조 영역이다.
- **행동:** 체결에서 포지션·비용·Trace로 이동하고 주문 문맥을 CEO에게 묻는다. `Cancel order` 등은 실제 지원/권한이 있을 때만 고정 패널로 연결한다.
- **상태:** 미구현. 응답 유실·취소와 체결 경합·일부 체결 조회 누락은 별도로 표현한다. 새 주문 제출이나 자동 재시도 기능을 이 상세에 추가하지 않는다.
- **판정기준:** 접수를 체결로, 취소 요청을 남은 의무 제거로 표시하지 않는다. 사용자가 주문 수량과 실제 체결·잔량 및 마지막 확인을 구별한다.

<a id="p-21"></a>
### P-21 — Rationale details
- **목적:** “누가 어떤 근거로 이 운용을 선택했고 이후 무엇이 확인됐는가?”에 답한다. 작성자/시점 → 당시 판단·근거 → 실제 결과/후속 판단 순서로 배치한다.
- **필요근거:** 실제 판단 기록과 revision·작성 구성원·당시 책임, 입력/대안/다음 조건 중 기록된 항목, 연결된 작업·아티팩트·외부 관측. 숨은 모델 사고를 근거로 주장하지 않는다.
- **표현:** `Rationale`, `Authored by`, `Written at`, `Evidence`, `Observed outcomes`, `Next review condition`. 현재 거래 사실과 작성된 해석을 분리하고 아바타/직함은 작성자 문맥만 전달한다.
- **행동:** 근거 파일·관측·원래 작업으로 이동하고 해당 판단 revision을 첨부해 CEO에게 질문한다. 다른 구성원의 판단을 현재 CEO의 새 설명으로 바꾸지 않는다.
- **상태:** v2 일부 있음/미구현. 포지션 안의 짧은 설명/파일 표시는 있으나 독립 판단 상세와 링크는 없다. 근거 부족·상충·이전 판단은 내용을 꾸미지 않고 표시한다.
- **판정기준:** 실제 효과와 판단의 예측/해석을 구별한다. 후속 수정이 이전 판단·실패를 지우지 않으며 긍정 설명만으로 수익성이나 권한이 생기지 않는다.

<a id="p-22"></a>
### P-22 — Ask CEO / Return / 정확한 개입 연결
- **목적:** “보고 있는 내용을 물어보거나 필요한 조치를 검토한 뒤 원래 투자 문맥으로 돌아갈 수 있는가?”를 모든 상세의 공통 마무리 행동으로 제공한다.
- **필요근거:** 선택 계정·기간·기록/revision, 현재 수신 책임과 대화 범위, 제어가 있으면 정확한 대상·현재 권한·실제 지원 여부. 참조 첨부는 새 자료 접근 권한이 아니다.
- **표현:** `Ask CEO` 또는 실제 이름, 제거 가능한 선택 문맥 chip, `Back to Portfolio`/닫기. 말풍선은 질문, 화살표는 이동이며 제어 완료를 뜻하지 않는다. 제어는 별도 고정 패널이다.
- **행동:** 선택한 계정값·기간 손익·주문·판단·파일을 정확히 첨부한다. Escape는 한 겹만 닫고 원래 선택/포커스/스크롤로 돌아간다. 실행 정지와 투자 제어는 다른 대상이다.
- **상태:** v2 일부 있음/개선. 현재 대화 문맥은 항상 동일 포지션이며 전송은 비활성이다. 미배정·전달 실패·답변 대기를 구별하고 질문 실패가 원본 열람을 막지 않는다.
- **판정기준:** 어느 값에서 질문했는지 사용자가 확인·제거할 수 있다. 재연결이 메시지/제어를 중복 제출하지 않고, 실행 정지를 포지션 정리로 표시하지 않는다.

## 문서와 화면의 완료 판단

각 P-ID는 해당 요소의 코드 주석/검토에서 참조한다. 단순 존재 여부보다 위의 질문과 행동이 연결되는지 확인한다.
관측된 v2 요소, 목적에 맞춘 개선, 미구현 상세를 구별해 보고한다. 이 문서의 작성은 해당 화면이나 실제 금융 연결의 완료가 아니다.
실제 화면 검토에서는 계정값→구성, 기간 손익→거래/비용, 포지션→주문/체결, 판단→근거→대화→원래 위치의 이동을 확인한다.
기존 공통 상태·브랜드·키보드/포커스 규칙은 반복 구현하지 않는다. 자료가 없는 경우도 숫자를 꾸미지 않고 같은 질문에 가능한 범위와 다음 행동으로 답해야 한다.
